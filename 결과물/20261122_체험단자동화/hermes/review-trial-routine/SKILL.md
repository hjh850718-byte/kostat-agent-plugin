# review-trial-routine — 체험단 스캔 · 신청 준비 · 리뷰 초안

## 0. 절대 규칙 (어기면 즉시 중단하고 보고)
1. **제출 금지**: 공개 댓글 등록, 체험단 신청 제출, 리뷰 등록, 결제(배송비 포함), 비밀번호·SNS 계정 입력은 하지 않는다. 초안과 입력 항목 목록만 만들어 건별 "승인"을 받은 뒤에만 실행한다.
2. **예약(cron) 실행은 항상 scan 모드.** 무인 실행에서는 읽기·정리·초안 저장까지만 한다.
3. **우회 금지**: 로그인 화면·캡차·본인인증·봇 차단(Cloudflare 등)이 나오면 멈추고 스크린샷과 함께 보고한다. 우회 시도 금지.
4. **자동 클릭 허용 범위**: 페이지 이동, 스크롤, 탭 전환, 필터·정렬 변경. 알림받기·찜은 승인 후(act 모드). 그 외 클릭은 금지.
5. **개인정보**: 주소·전화번호·실명·이메일을 폼에 자동 입력하거나 결과 파일·노션에 적지 않는다. "직접 입력" 항목으로만 표시한다.
6. **어뷰징 방지**: 사이트당 하루 1회, 동작 사이 1~3초 랜덤 대기, 승인 후 제출도 실행당 3건 이내.
7. **추정 금지**: 화면에 없는 수치(경쟁률, 마감, 원고료)는 "확인 불가"로 적는다. 캠페인 조건(글자수·사진 수·필수 해시태그·기한)은 안내 문구 원문 값만 쓴다.
8. **써보지 않은 내용은 쓰지 않는다**: 리뷰 본문은 사용자가 준 사용 메모·사진 설명에 있는 사실만 쓴다. 빈 항목은 질문한다.

## 2. 모드
- **scan** (기본·예약 실행): 읽기 → 후보표 → 승인 대기 목록. 외부 제출 없음.
- **act**: 승인한 항목만 알림받기·찜.
- **draft**: 신청 기대평 / 리뷰 초안 작성. 외부 제출 없음.
- **submit**: 승인한 항목만 제출. 건별 승인, 기본 비활성.

## 3. 단계별 절차

### 3.1 네이버 무료체험 (매일)
1) 목록 로드 후 스크롤 3~5회.
2) 읽을 항목: 상품명, 브랜드, 마감일, 모집인원, 신청수(표시될 때), 배송비, 필수 미션, 당첨 후 페널티.
3) 우선순위: 마감 3일 이내 → 배송비 0원 → 블로그 후기 미션 → 경쟁률(신청수÷모집인원) 낮은 순.
4) 표: 순위 | 상품명 | 마감(D-n) | 배송비 | 경쟁률 | 필수 미션 | 페널티 | 링크
5) 상위 3건은 act 승인 요청(알림받기+찜).

### 3.2 네이버 한달사용리뷰 (매월 1일)
- 주소: https://shopping.naver.com/my/writable-reviews
- 표: 상품명 | 구매일 | 마감(D-n) | 포인트 | 조건 | 링크
- 한 줄: 이번 달 포인트 총합 / 놓치면 사라지는 포인트.
- 리뷰 본문은 사용자 메모가 있을 때만 다듬는다.

### 3.3 무신사 체험단 (월·수·금)
1) 신규(당일) / 마감임박 필터.
2) 선정 기준: ① 출근·일상복으로 실제 쓸 제품 ② 경쟁률 낮음 ③ 마감 임박 ④ 요구 채널이 무신사 후기 또는 네이버 블로그.
3) 표: 순위 | 브랜드·상품 | 마감(D-n) | 경쟁률 | 제공 내역 | 요구 채널 | 리뷰 조건 | 추천 이유(1줄)
4) 상위 3건 draft: 기대평 버전 A(일상 착용 계획) / B(블로그 리뷰 계획 포함) 각 2~3문장, 해시태그 3~5개(필수 해시태그 먼저), 폼 입력 항목 번호 목록(사이즈 1장 값, 개인정보는 "직접 입력").
5) 봇 차단 페이지가 뜨면 0-3 규칙대로 멈춘다. 사용자가 캠페인 링크·안내 문구를 직접 주면 그것으로 4)를 진행한다.

### 3.4 배송형 블로그 체험단 — 레뷰·강남맛집·서울오빠 (화·목)
1) 배송형(택배 수령)만. `include_visit_type: true`일 때만 방문형(부천·인천·서울 서부) 포함.
2) 표: 사이트 | 캠페인 | 제품 | 모집/신청 | 마감 | 요구 채널 | 원고료·포인트 | 링크
3) 신청 멘트 초안: 블로그 주제와 연결되는 각도 1줄 + 3문장 소개.
4) 자격 조건(블로그 지수·이웃수·최소 글수)은 원문 그대로 적고 충족 여부는 사용자에게 확인.
5) 서울오빠는 '추가 정보' 미등록이면 초안에 "추가 정보 등록 필요" 표시.

### 3.5 당첨·수령 후 리뷰 (사용자가 당첨/수령을 알려줄 때)
1) 질문을 한 번에 묶어서 보낸다:
   1. 받은 날짜 / 실제 사이즈·컬러
   2. 첫인상(포장·소재·마감) 한 줄
   3. 사용·착용 장면 2~3개(언제, 어디서, 얼마나)
   4. 사이즈감(평소 대비, 어깨·기장·발볼 등)
   5. 좋았던 점 2개 / 아쉬운 점 1개
   6. 세탁·관리 경험(했으면)
   7. 사진 목록(전체샷, 디테일, 착용샷, 사이즈 비교 등)
   8. 캠페인 리뷰 조건과 작성 기한(안내 문구 원문)
2) 플랫폼 리뷰(무신사 등): 조건 글자수 맞춤. 구성 = 사이즈 정보 → 사용감 → 좋은 점 → 아쉬운 점 → 추천 대상 1줄.
3) 블로그 글: 제목 3안 + 본문 1,500~2,000자 + 사진 위치 `[사진1: 전체샷]` + 해시태그 + 출근룩·출장 짐·사무실 같은 생활 각도 1개.
4) **협찬 표기**: 블로그 글 첫 줄과 마지막 줄에 "○○ 체험단으로 제품을 무상 제공받아 직접 사용 후 작성했습니다." 캠페인 안내에 표기 규칙(배너·문구)이 있으면 그것을 우선한다. 글 안에 제휴 링크(쿠팡 파트너스 등)를 넣는 경우 그 고지도 같은 글 본문 첫 부분에 별도로 넣는다.
5) 체크리스트: 글자수 / 사진 수 / 필수 해시태그 / 협찬 표기 / 작성 기한(D-n).
6) "승인"이면 붙여넣기용 최종본만 다시 준다. 블로그는 임시저장까지, 발행은 사용자가 한다.

## 4. 상태 파일 (중복 방지)
- 경로: 작업 폴더의 `review-trial/state.json`
```json
{
  "reported": ["<링크>", "..."],
  "applications": [
    {"date": "YYYY-MM-DD", "site": "musinsa", "item": "상품명", "link": "...", "status": "신청|당첨|미당첨|수령|리뷰작성|등록완료", "review_due": "YYYY-MM-DD"}
  ]
}
```
- 이미 reported에 있는 링크는 다시 후보표에 올리지 않는다(마감 D-1이면 "마감 임박 재알림"으로 1회만 예외).
- review_due가 D-3이 되면 매일 결과 첫 줄에 리마인드.

## 5. 출력 형식 (매 실행)
- 제목: `[체험단 루틴] YYYY-MM-DD HH:MM · 단계명`
- 첫 줄 결론: `신규 n건 / 마감임박 n건 / 승인 대기 n건 / 리뷰 기한 임박 n건`
- 단계별 표
- 승인 요청 블록: 동작 | 대상 | 예상 소요 | 되돌릴 수 있는지
- 다음 마감 3건
- 마지막 줄: 사용자가 지금 할 일 1개
- 저장: `review-trial/logs/YYYY-MM-DD_단계명.md` (항상). 노션 도구가 있으면 협업 허브 📤 섹션에도 같은 요약을 남기고, 없으면 결과 첫 줄에 "노션 미연결".

## 6. 실패 처리
- 로그인 필요 / 캡차 / 본인인증 / 봇 차단: 중단 + 스크린샷 + 보고.
- 요소를 못 찾음(사이트 개편): "구조 변경 의심"으로 보고. 추측 클릭 금지.
- 같은 오류 2회: 그 사이트는 그날 중단하고 다음 단계로.
