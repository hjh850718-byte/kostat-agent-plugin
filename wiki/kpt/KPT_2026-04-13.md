# KPT 회고 — 2026.04.13 (월 저녁)

## K (Keep) — 잘됐다, 계속 해야 할 것

**1. 계약서 리스크 선제 식별**
YTEC 承諾書에서 불리한 조항 3건을 명확히 구분하고 HIGH/MEDIUM 리스크로 분류했다. 단순 번역이 아니라 비즈니스 리스크 관점에서 분석한 점이 좋았다.

**2. 영문 협상 서한 2버전 전략**
"정중한 협상 요청"과 "간결한 수정 요청" 2버전을 상황에 맞게 준비한 방식은 실전에서 유용하다. 상황에 따라 바꿔 쓸 수 있는 준비가 된 것.

**3. CLAUDE.md 체계화**
기존 범용 원칙에 KOSTAT 전용 섹션(§5~§10) 추가 완성. 커미션 인보이스, PO 파싱, 번역 용어집 등 반복 업무를 코드화한 것은 장기적으로 토큰 절감 + 품질 일관성 확보에 직결된다.

**4. 업무끝 루틴 정착**
Notion 저장 → 캘린더 브리핑 예약 → KTP 회고 순서가 자리잡혀 가고 있다. 매일 이 루틴을 유지하면 다음날 아침 출근 준비가 30% 빨라진다.

## T (Try) — 다음에 시도해볼 것

**1. YTEC 서명 전 결재 루트 확정**
협상 서한 발송 전 김인섭 부장님 검토 → 법무 또는 영업 책임자 확인 순서를 내일 아침 먼저 정리할 것. 타이밍 놓치면 계약 관계에 영향 생김.

**2. CLAUDE.md → Claude Code 실제 배치 테스트**
완성된 CLAUDE.md를 `~/.claude/CLAUDE.md`에 실제 배치하고 Claude Code 세션에서 KOSTAT 컨텍스트가 자동 주입되는지 확인. 특히 커미션 인보이스 작업에서 효과 검증.

**3. Notion 업무 트래커 실 사용 시작**
DB만 만들고 끝나지 않도록, 내일부터 실제 업무 1건 이상 트래커에 등록 + 상태 업데이트 습관 시작. Micron HBM4E 건부터 시범 운용.

**4. GitHub 연동 방식 전환**
Claude.ai에서는 GitHub 직접 조작 불가 확인. Claude Code CLI 사용 or GitHub Actions + Anthropic API 자동화 쪽으로 방향 전환 검토.

→ 내일 오전 중 부장님께 검토 요청 필수

**3. 대화창 분산으로 맥락 단절**
