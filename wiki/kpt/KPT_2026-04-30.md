# KPT 회고 — 2026.04.30 (목 저녁)

## K (Keep) — 잘됐다, 계속 해야 할 것

**1. 프롬프트 마스터(Prompt Master) 스킬 체계적 검토**
- GitHub 기반 Claude 스킬(github.com/nidhinjs/prompt-master) 분석 완료
- 핵심 가치: 9개 Intent Dimension 추출 → 토큰 낭비 패턴 제거 → 세션간 메모리 지속성
- KOSTAT 해외영업 업무에 적용 가능한 구조 확인

**2. GitHub 기반 설치 방식 학습**
- 표준 Claude 인터페이스 한계 명확화 (`/add-marketplace`, `/install` 커맨드 미지원)
- 직접 설치(`npm install`) vs 프로젝트 루트 통합 vs CLAUDE.md 모듈화 세 가지 옵션 정리

**3. KOSTAT 특화 프로필 설정 재확인**
- 사용자 선호사항 정리: 토큰 효율성 우선, 대규모 작업은 사전 확인
- PO 업데이트, 커미션 인보이스, OOR 처리 등 주요 업무 맥락 재검증
- 역할 명확화: 상사에게 보고할 데이터/옵션/제안서 작성 중심

## Problem (Trouble) — 막혔거나 애먹었던 것

**1. 초기 커맨드 탐색 혼선**
Prompt Master 설치 초반, 표준 Claude 인터페이스에 없는 커스텀 커맨드로 시도. 결국 공식 문서 검토 후 정상 설치 경로 확인 (20분 소모). 원인: 다양한 도구/플랫폼 정보 혼재로 인한 가정 실수

**2. 대규모 구현 결정 지연**
3가지 통합 옵션 제시 후 최종 방향 선택 미완료. "토큰 효율성 검증을 위해 어느 방식을 먼저 시도할지?" → 다음 세션으로 미룸

## Try — 다음에 시도할 것

**1. 프롬프트 마스터 프로토타입 구현**
선택된 통합 옵션(standalone / agent / CLAUDE.md) 기반 작은 규모 파일럿 구성. 실제 PO 업데이트 작업 1건 → Prompt Master 원칙 적용 → 토큰 효율성 비교

**2. KOSTAT 특화 프롬프트 템플릿 라이브러리 구축**
Prompt Master의 9개 Intent Dimension을 KOSTAT 도메인에 매핑:
- Clarity(명확성) → PO 컬럼 정의, 고객사 코드명 기준
- Specificity(특수성) → 국가별 배송 규칙, 커미션 요율
- Conciseness(간결성) → OOR 루틴 자동화 스크립트
- Actionability(실행성) → PO DATE ~ Ship To 자동 파싱
- Tone(톤) → 상사 보고 vs 거래처 메일 구분
- 재사용 가능한 템플릿 3~5개 작성

**3. 최종 옵션 선택 및 구현 계획 수립**
다음 세션 시작 시 명확한 결정: 설치 방식, 일정, 담당 에이전트 할당. 구현 비용 사전 토큰 견적 요청 (메모리: 사용자 선호사항)

## 내일 우선순위 (2026.05.01)

1. Prompt Master 통합 방식 최종 선택 (3분 의사결정)
2. 간단한 프로토타입 (standalone 기반 hello-world 설정, 15분)
3. 기존 PO 업데이트 작업 1건에 적용 (실제 효과 측정, 30분)
4. 결과 정리 및 다음 주 전략 수립 (KPT 페이지 작성)

> 메모: 토큰 효율성이 핵심 KPI. 구현 과정에서 비용 대비 효과 지속 모니터링. 이번 주말까지 의사결정 완료 목표.
