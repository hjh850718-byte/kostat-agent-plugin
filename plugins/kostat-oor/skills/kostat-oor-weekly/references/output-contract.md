# 출력 계약 — Evidence 형식 (모든 KOSTAT 스킬 공통)

REA의 Evidence 구분(관찰/유도/추론/미확인)을 영업 업무에 맞게 적용한 공통 규칙.
스킬별 적용 필드는 각 `skills/*/SKILL.md`의 "Evidence 적용" 섹션에 있다.

## 1. 라벨 정의

| 라벨 | 기호 | 의미 | 쓰기 허용 |
|------|------|------|-----------|
| 확인됨 | ✅ | 원본(PDF/Excel/메일/캘린더)에 그대로 존재. 출처 위치를 댈 수 있음 | 자동 |
| 계산됨 | 🧮 | 확인됨 값에서 **결정적 규칙**으로 도출 (수식, 날짜 차이, 요율 역산) | 자동 (수식 명시) |
| 추정 | ❓ | 근거는 있으나 원본에 없음 (기본값, 과거 패턴, 분류 휴리스틱) | **사용자 승인 후** |
| 미확인 | ⛔ | 알 수 없음 (추출 실패, 빈 셀, 식별 불가) | **쓰지 않음** — 빈칸 유지 + 알림 |

판정 원칙
- 출처를 대지 못하면 `확인됨`이 아니다.
- 규칙이 결정적이지 않거나 입력 중 하나라도 `추정/미확인`이면 결과도 `추정/미확인`이다 (등급은 가장 낮은 입력을 따름).
- **빈 값 ≠ 불일치.** 비교 대상 한쪽이 `미확인`이면 "불일치"가 아니라 "비교 불가(미확인)"로 분류한다.
- 한 번 낮춘 등급은 사용자 확인 없이 올리지 않는다. 사용자가 확인하면 `확인됨(사용자 확인)`으로 기록한다.

## 2. 필드 단위 기록 형식

처리 결과의 모든 필드는 값과 근거를 함께 가진다 (Task 출력 JSON, 로그, Trace Log 공통).

```json
{
  "po_number": {"value": "6000046947", "label": "확인됨", "source": "PO.pdf p1 헤더"},
  "mfg_site":  {"value": "KR", "label": "추정", "source": "신규 PN — 기본값 규칙", "needs_approval": true},
  "temp":      {"value": null, "label": "미확인", "source": "PDF에 TEMP 항목 없음"},
  "priority":  {"value": "🔴", "label": "계산됨", "source": "Need By 2026-10-20 − 기준일 2026-10-15 = 5일 ≤ 14"}
}
```

규칙: `source`는 파일명+위치(페이지/셀/시트) 또는 수식. 100자 이내. 고객 단가·원가 등 민감 값은 source에 값 자체를 복사하지 않고 위치만 적는다.

## 3. 보고 형식 (Telegram / 채팅 공통)

첫 줄에 요약, 이어서 `추정·미확인`만 펼쳐서 보여준다 (확인됨·계산됨은 건수만).

```
📋 {스킬명} {대상} — ✅ 12 · 🧮 3 · ❓ 1 · ⛔ 1
⚠️ 승인 필요
 ❓ mfg_site = KR  (신규 PN, 기본값 규칙) → 승인 / 수정
 ⛔ temp = (비어 있음)  (PDF에 항목 없음)
```

`❓/⛔`가 0건이면 첫 줄 한 줄만 보낸다.

## 4. 쓰기 게이트 (fail-closed)

1. 식별 필드(고객사, PO#, 금액, 납기)가 `추정/미확인`이면 **어떤 파일에도 쓰지 않고** 중단 후 질문.
2. 그 외 필드가 `추정`이면 변경 계획 표에 ❓로 표시하고 승인 후 기록. `미확인`은 빈칸 유지.
3. 변경 계획 표: `파일 | 시트 | 행 | 컬럼 | 현재값 | 새 값 | 라벨`.
4. fanout/자동 실행(Task Scheduler, POP3) 모드에서는 승인할 사람이 없으므로 `추정/미확인`을 쓰지 않고 `status: "needs_review"`로 반환 → 취합 단계에서 한 번에 알림.
5. 재처리 시 같은 PO#/키는 갱신(멱등). 값이 달라지면 "이전값 → 새값"을 계획 표에 표시.

## 5. 검증(Evaluator/체크리스트) 공통 항목

- [ ] 모든 출력 필드에 label이 있다 (라벨 없는 값 0건)
- [ ] `확인됨`은 source를 가진다
- [ ] `계산됨`은 수식과 입력값이 재현 가능하다 (독립 재계산 일치)
- [ ] `추정/미확인` 값이 승인 없이 파일에 쓰이지 않았다
- [ ] 보고 첫 줄의 건수 합계 = 필드 수
- [ ] 비교 불가(미확인)를 불일치로 집계하지 않았다

## 6. 라벨 → 다른 체계 매핑

| 본 계약 | Memory Ticket `trustLabel` | Trace Log |
|---------|----------------------------|-----------|
| 확인됨·계산됨 | confirmed / validated | 근거요약에 건수 |
| 추정 | proposed | 근거요약에 건수 (비고에 필드명) |
| 미확인 | (저장 금지) | 근거요약에 건수 (비고에 필드명) |
