# AI 위임 매뉴얼 루프 — KOSTAT 11개 스킬 적용 프롬프트

> 출처: "AI 위임 루프: 에이전트 대신 매뉴얼으로 일 넘기기" 가이드 (2026.9.18)
> 이 문서는 그 가이드의 프롬프트 4종을 KOSTAT 플러그인의 11개 스킬에 맞게 채운 버전이다.
> **로컬 Claude Code(파일 접근 가능한 환경)에서 하나씩 순서대로 실행한다.**
> 각 프롬프트는 그대로 복사해서 새 대화에 붙여넣으면 된다.

## 왜 이 문서가 필요한가

현재 `kostat-agent-plugin/skills/*/SKILL.md` 11개는 전부 **프로세스 레이어만** 있다.
`files/`(툴박스), `examples/`, `notes.md`, "완료의 정의(증명 레이어)"가 없다.
그 결과 매번 같은 스크립트·같은 표기 규칙을 처음부터 다시 만들고, 검증 없이 결과물을 내놓고,
같은 실수가 반복돼도 기록이 남지 않는다.

또한 `kostat-po-update`, `kostat-hk-po-update`, `kostat-oor-weekly`, `kostat-commission-invoice`,
`kostat-eod-retrospective`는 Fan-out(병렬 서브에이전트) 구조를 쓴다. 가이드의 핵심 주장은
"에이전트를 계속 쪼개지 말고, 범용 에이전트 하나에 매뉴얼 폴더를 줘라"이므로, 이 5개는
**0단계(구조 단순화 검토)**를 먼저 거친다.

## 작업 순서 (우선순위)

| 순서 | 스킬 | 이유 |
|---|---|---|
| 1 | `kostat-po-update` | 주 1회 이상, 나쁜 버전이 한눈에 보임(수량/단가 오류), 반복 빈도 최고 |
| 2 | `kostat-oor-weekly` | 주간 고정 반복, 컬러코딩·불일치 표기 규칙이 이미 명확 |
| 3 | `kostat-hk-po-update` | PO-update와 구조 유사, 2번째로 채우면 툴박스 재사용 가능 |
| 4 | `kostat-commission-invoice` | 월 1회지만 금액 오류 리스크 높음(요율 역산) |
| 5 | `kostat-morning-briefing` | 매일 실행, 검증 항목이 현재 0개 |
| 6 | `kostat-eod-retrospective` | 매일 실행, Notion 저장 — 실패 시 데이터 유실 리스크 |
| 7~11 | `kostat-memory-loader`, `kostat-memory-ticket`, `kostat-skill-check`, `kostat-tal`, `kostat-orchestrator` | 인프라/판단기준 스킬. 아래 "인프라 스킬" 절 참고 |

**한 번에 하나씩만 진행한다.** 1번을 완전히 끝내고(증명 통과 확인까지) 2번으로 넘어간다.
동시에 여러 개를 돌리면 가이드가 경고하는 "거대 폴더 하나" 실수와 같은 효과가 난다.

## 0단계 — Fan-out 구조 단순화 검토 (5개 스킬 전용)

`kostat-po-update`, `kostat-hk-po-update`, `kostat-oor-weekly`, `kostat-commission-invoice`,
`kostat-eod-retrospective`에 대해, 매뉴얼화(1~4단계) 전에 **딱 한 번** 아래 프롬프트를 먼저 돌린다.

### 붙여넣기 프롬프트 0 — Fan-out을 단일 매뉴얼로 단순화할지 판단

```
kostat-agent-plugin/skills/[job-name]/SKILL.md 를 읽어라.

이 스킬은 지금 Fan-out(병렬 서브에이전트 2way/3way) 구조로 되어 있다.
아래 기준으로 이 구조가 실제로 필요한지 판단해라:

1. 서브에이전트들이 서로 다른 데이터 소스를 완전히 독립적으로 처리하는가,
   아니면 결국 같은 파일 하나를 순서대로 고치는가?
2. 병렬로 나눴을 때 얻는 시간 이득이, 결과를 취합/검증하는 데 드는 복잡도보다 큰가?
3. 범용 에이전트 하나가 이 SKILL.md + 툴박스 폴더만 보고 처음부터 끝까지
   순서대로 처리해도 결과 품질이 같은가?

셋 다 "아니오"거나 애매하면: 이 스킬을 **단일 순차 실행 모드로 재작성**해라.
Fan-out 모드는 "실행 모드 선택" 섹션에 남기되 기본값을 단일 모드로 바꾸고,
언제 병렬이 실제로 필요한지(예: 완전히 독립된 3개 고객사 파일을 동시에 열어야 할 때)만
예외로 남겨라.

하나라도 "예"이고 병렬이 실제로 시간을 아낀다면: 구조는 유지하되,
아래 1~4단계는 "취합 후 결과물" 기준으로 적용한다고 SKILL.md 맨 위에 한 줄로 적어라.

수정한 SKILL.md 전체를 보여주고, 어느 판단을 내렸는지 이유 두 문장으로 말해라.
파일을 직접 쓸 수 없다면 쓴 척하지 말고 전체 내용을 출력해라.
```

`[job-name]`을 스킬 폴더명(예: `kostat-po-update`)으로 바꿔서 사용한다.

---

## 1단계 — 기존 SKILL.md 갭 진단 (가이드 프롬프트 1의 변형)

가이드 원본은 "빈 상태에서 인터뷰"지만, KOSTAT은 이미 SKILL.md가 있으므로
**처음부터 다시 쓰지 않고 갭만 인터뷰로 채운다.**

### 붙여넣기 프롬프트 1 — 기존 스킬을 매뉴얼 3레이어로 보강

```
kostat-agent-plugin/skills/[job-name]/SKILL.md 전체를 읽어라.

이 파일은 이미 프로세스 레이어(목적/트리거/입력/순서/결정)는 어느 정도 있다.
지금부터 나를 인터뷰해서 빠진 부분만 채워라. 한 번에 질문 하나만 하고 답을 기다려라.
최소 여섯 개 질문을 하고, 내가 끝났다고 말하기 전까지 파일을 고치지 마라.
아래를 반드시 확인해라:

- SKILL.md에 없는 예외 사례 (이 업무를 하다가 예전에 나를 태운 적 있는 케이스)
- 지금 매번 처음부터 다시 만들고 있는 스크립트/템플릿/참조표가 있는지
  (있다면 실제 위치와 파일명)
- "끝났다"고 부르기 전에 내가 눈으로 직접 확인하는 것들 (완료의 정의 후보)
- 결정 규칙 중 SKILL.md에 안 적혀 있지만 내 머릿속에만 있는 것
- 고객사명/PO 표기/컬러코딩처럼 매번 똑같이 참조하는 고정 데이터

인터뷰가 끝나면:
1. `kostat-agent-plugin/skills/[job-name]/files/` 폴더 구조를 제안해라
   (스크립트, 템플릿, 참조 데이터 각각 어떤 파일이 필요한지)
2. `kostat-agent-plugin/skills/[job-name]/examples/` 에 넣을 "잘 됐던 예시" 후보를
   최근 작업 중에서 물어봐라
3. SKILL.md에 없던 예외 사례와 결정 규칙을 반영해 수정된 SKILL.md 전체를 보여줘라
   (기존 섹션 구조와 톤은 유지, 새로 필요한 섹션만 추가)

파일을 직접 쓸 수 없다면 쓴 척하지 마라. 전체 파일 내용을 채팅에 출력하고,
정확한 파일명과 폴더 안 위치를 알려주고, 기존 SKILL.md를 지우고 새걸로
교체하라고 나에게 상기시켜라.
```

## 2단계 — 통과한 산출물을 툴박스로 저장

1단계 직후, 실제로 그 업무를 한 번 돌린 뒤 결과가 괜찮으면 바로 실행한다.

### 붙여넣기 프롬프트 2 — 산출물을 files/에 저장

```
방금 만든 [스크립트 / 템플릿 / 체크리스트 / 참조표]를 봐라.

내가 이걸 또 필요로 하게 되면, 다음을 전부 해라:
1. kostat-agent-plugin/skills/[job-name]/files/ 에 설명적인 이름으로 저장해라.
   예: numbers-pull.py, po-template.md, customer-names.md. 날짜/버전 번호는 넣지 마라.
2. 이번 건에만 특화된 부분(고객사명, 금액, PO#)을 대괄호 자리표시자로 바꿔
   재사용 가능하게 만들고, 바로 아래에 채워진 예시 하나를 참조로 남겨라.
3. SKILL.md를 업데이트해서 이 단계가 이 파일을 이름으로 가리키게 하고,
   언제 쓰고 언제 안 쓰는지도 적어라.
4. kostat-agent-plugin/skills/[job-name]/files/INDEX.md 에 한 줄 추가해라:
   파일명, 용도, 오늘 날짜(YYYY-MM-DD).

일회성 산출물, 비밀번호나 계정 정보가 담긴 것, 내가 승인하지 않은 초안은 저장하지 마라.

그리고 같은 업무를 처음부터 다시 돌리고, 어떤 저장된 파일을 썼고 무엇을
백지에서 다시 지었는지 알려라. 다시 지은 것은 전부 툴박스 후보니, 다음에
뭘 저장할지 말해라.

파일을 직접 쓸 수 없다면 쓴 척하지 마라. 전체 파일 내용을 채팅에 출력하고,
정확한 파일명과 폴더 안 위치를 알려주고, 업로드된 예전 복사본을 지우고
새걸로 교체하라고 나에게 상기시켜라.
```

## 3단계 — 실패할 수 있는 검증 항목 추가

### 붙여넣기 프롬프트 3 — 완료의 정의 만들기

```
kostat-agent-plugin/skills/[job-name]/SKILL.md 에 "완료의 정의" 섹션을 추가/보강해라.

이 업무에 특화된 검증 항목 5~10개를 써라. 모든 항목은 내 의견 바깥의 증거로
확인 가능해야 한다: 원본 PDF/xlsx 파일까지 추적되는 숫자, 참조 파일(customer-names.md
등)과 대조된 표기, 행/개수 일치, 실제로 열리는 파일 경로, 컬러코딩 규칙과 대조된 셀 색상,
전월/전주 값과의 증감 대조. "명확한", "정확한", "깔끔한" 같은 애매한 단어는 쓰지 마라.

이제부터 이 업무를 마칠 때마다, 나에게 결과물을 보여주기 전에:
1. 모든 검증 항목을 돌려라.
2. 실패한 걸 고쳐라.
3. 다시 돌려라.
4. 항목마다 근거와 함께 한 줄짜리 통과/실패를 내놔라.
5. 확인할 수 없는 것은 뭔지, 왜인지를 말해라. 통과한 걸로 가정하지 마라.

첫 패스에서 두 개보다 많은 항목이 실패하면 멈추고, 결과물을 땜질하지 말고
어느 프로세스 단계가 원인이었는지 말해라.

파일을 직접 쓸 수 없다면 쓴 척하지 마라. 전체 파일 내용을 채팅에 출력하고,
정확한 파일명과 폴더 안 위치를 알려주고, 업로드된 예전 복사본을 지우고
새걸로 교체하라고 나에게 상기시켜라.
```

## 4단계 — 채팅이 아니라 매뉴얼을 고치는 루프

결과가 틀렸을 때마다 즉시 실행한다. 절대 채팅에서만 고치고 넘어가지 않는다.

### 붙여넣기 프롬프트 4 — 잘못된 결과를 레이어 진단으로 고치기

```
[job-name]의 결과물이 틀렸다. 이유는: [무엇이 어떻게 잘못됐는지 정확히].

먼저 어느 레이어가 실패했는지 진단해라:
- 프로세스: SKILL.md에 단계가 빠졌거나 순서가 틀렸거나 결정 뒤의 규칙이 안 적혔다
- 툴박스: files/에 이미 있는 걸 다시 지었거나, 저장된 파일(참조표 등)이 낡았거나 틀렸다
- 증명: 이걸 잡았을 검증 항목이 "완료의 정의"에 없었다

어느 것이었고 왜인지 두 문장으로 말해라.

그리고 그 레이어에 가장 작은 내구성 있는 수정을 해라. SKILL.md 전체를 다시 쓰지 마라.
같은 실수가 이제 두 번 일어났다면 부드러운 리마인더가 아니라 그걸 막는
명시적 검증 항목이나 규칙을 추가해라.

kostat-agent-plugin/skills/[job-name]/notes.md 에 오늘 날짜, 무엇이 잘못됐는지,
무엇을 바꿨는지 한 줄을 맨 위에 추가해라 (최신이 위로).

그리고 같은 작업을 처음부터 다시 돌리고, 수정 전과 후를 보여줘라.

파일을 직접 쓸 수 없다면 쓴 척하지 마라. 전체 파일 내용을 채팅에 출력하고,
정확한 파일명과 폴더 안 위치를 알려주고, 업로드된 예전 복사본을 지우고
새걸로 교체하라고 나에게 상기시켜라.
```

`notes.md`는 한 달에 한 번 훑어본다. 같은 스킬, 같은 레이어에 기록이 반복되면
그 업무가 진짜 어려운 지점이라는 뜻이고, 다음 자동화 우선순위가 된다.

## 인프라 스킬 (7~11번) — 다르게 다룬다

`kostat-memory-loader`, `kostat-memory-ticket`, `kostat-skill-check`, `kostat-tal`,
`kostat-orchestrator`는 "반복되는 하나의 업무"가 아니라 다른 스킬들을 돕는 인프라다.
가이드의 프레임을 그대로 적용하면 안 맞으니 아래처럼 변형한다.

- **kostat-tal, kostat-memory-loader**: "완료의 정의"만 3단계 프롬프트로 추가한다
  (예: 로드된 컨텍스트가 실제 소스 파일 경로를 가리키는지, 오래된 캐시가 아닌지).
  0/1/2단계는 생략해도 된다 — 툴박스랄 게 없는 순수 로더이기 때문이다.

- **kostat-memory-ticket, kostat-skill-check**: 1, 3, 4단계만 적용한다.
  (2단계 툴박스는 생성되는 티켓 포맷 템플릿 하나 정도만 `files/`에 저장하면 충분)

- **kostat-orchestrator**: 이게 Option C의 핵심 재구성 대상이다. 위 0단계 프롬프트를
  변형해서 아래처럼 별도로 돌려라.

### 붙여넣기 프롬프트 0-B — Orchestrator를 라우터로 축소할지 판단

```
kostat-agent-plugin/skills/kostat-orchestrator/SKILL.md 전체를 읽어라.

가이드의 핵심 주장: "일마다 에이전트를 새로 만들지 말고, 범용 에이전트 하나에
매뉴얼 폴더를 줘라". 지금 kostat-orchestrator는 트리거를 감지해서 여러 핸들러/스킬로
쪼개 보내는 Level 7 구조다.

각 하위 스킬(kostat-po-update 등)이 1~4단계를 거쳐 자기 완결적 매뉴얼
(SKILL.md + files/ + examples/ + notes.md)이 되고 나면, orchestrator가 실제로
해야 할 일은 "트리거를 보고 맞는 스킬 폴더 하나를 골라 넘기는 것"뿐이어야 한다.
그 이상의 로직(데이터 가공, 취합, 재시도 판단)이 orchestrator 안에 남아있다면
전부 해당 하위 스킬로 옮겨라.

수정된 kostat-orchestrator/SKILL.md 전체를 보여줘라. 트리거→스킬 매핑 표는
유지하되, 그 외 로직이 얼마나 줄었는지 줄 수로 비교해서 말해라.

파일을 직접 쓸 수 없다면 쓴 척하지 마라. 전체 파일 내용을 채팅에 출력하고,
정확한 파일명과 폴더 안 위치를 알려주고, 기존 SKILL.md를 지우고 새걸로
교체하라고 나에게 상기시켜라.
```

## 완성된 폴더 모습 (11개 스킬 각각)

```
skills/[job-name]/
  SKILL.md              목적, 트리거, 입력, 순서, 결정, 완료의 정의, 예외 사례
  files/
    INDEX.md            저장된 파일마다 한 줄: 이름, 용도, 날짜
    [스크립트/템플릿/참조표...]
  examples/
    YYYY-MM-DD-good.md  만족했던 완성 작업
  notes.md              수정 기록, 최신이 위로
```
