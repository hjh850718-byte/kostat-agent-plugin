# [보고] 자동화 오입력 방지 및 이상 알림 체계 도입 건

해외영업부 한준희 과장 / 2026-11-07

## 1. 배경
- PO, HK PO, 커미션 인보이스 작업이 자동화되어 있으나, 기존 파일 수정 시 확인이 "세션당 첫 1회"뿐이다.
- 병렬 처리(서브에이전트) 중에는 이 확인이 적용되지 않는다.
- 파싱 실패, 금액 불일치 시 담당자에게 알리는 정해진 경로가 없다.

## 2. 제안
| 구분 | 내용 | 기대 효과 |
|---|---|---|
| A. 승인 단계화 | 작업을 4단계(읽기 / 신규 생성 / 기존 파일 수정 / 금액·발송)로 나눠, 금액·발송은 항상 담당자 승인 | 오입력·덮어쓰기 방지 |
| C. 이상 알림 | 파싱 실패·금액 불일치·승인 대기 등 5개 조건에서 텔레그램 알림 (같은 건 1시간 3회 제한) | 문제 누락 방지 |

참고: 오픈소스 OpenMausBot의 승인 단계·에스컬레이션 설계 개념을 차용하며, 외부 도구 도입 없이 기존 Hook과 텔레그램 모듈을 확장한다.

## 3. 옵션 비교
| 옵션 | 범위 | 공수(추정) | 비고 |
|---|---|---|---|
| 1 | A만 | 2~3일 | 알림 없음 |
| 2 | C만 | 3~5일 | 잘못된 쓰기는 못 막음 |
| **3 (추천)** | A+C | 5~8일 | 단계 도입: 경고 모드 → 알림 → 강제 모드 |

## 4. 일정
총 약 4주: 규칙 확정·경고 모드(1주) → 알림 구현(1주) → 시범 운영 후 강제 전환(2주)

## 5. 리스크
- 확인 단계가 늘면 속도 저하 가능 → 신규 생성은 자동 처리, 수정은 변경 요약 1회 확인으로 완화
- 알림 과다 → 조건 5개로 제한, 폭주 방지 적용
- 알림에 거래처 정보 포함 → 금액 상세는 제외 권장

## 6. 결정 요청
1. 도입 옵션 (1 / 2 / 3)
2. 텔레그램 알림에 포함할 정보 범위
3. 시범 운영 기간 (2주 제안)

※ 공수·일정은 추정치이며 착수 전 재산정한다. 상세 내용은 별첨 "11. 승인 단계화·에스컬레이션 도입 제안서" 참고.
