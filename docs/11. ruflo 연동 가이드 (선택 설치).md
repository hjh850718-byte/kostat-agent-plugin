# ruflo 연동 가이드 (선택 설치)

> `ruvnet/ruflo`(npm: `ruflo`, 구 `claude-flow`)를 로컬 PC에 설치해 Claude Code와 MCP로 연동하고,
> hierarchical swarm(8-agent)을 초기화하는 절차. **kostat-agent-plugin과는 독립적인 별도 프로젝트**이며,
> 이 문서는 팀원이 로컬 환경에서 직접 실행하기 위한 참고 가이드다. KOSTAT-AGENT의 실제 PO/OOR/커미션
> 업무는 계속 `kostat-orchestrator` 스킬이 담당하며, ruflo가 이를 대체하지 않는다.

관련 문서: [08. KOSTAT Plugin 패키징 설계](./08.%20KOSTAT%20Plugin%20패키징%20설계.md) · `skills/kostat-orchestrator/SKILL.md`

---

## 1. ruflo란

Ruflo는 Claude Code / Cursor / Codex 등 여러 AI 코딩 에이전트 위에서 동작하는 **범용 멀티에이전트 오케스트레이션 레이어**다.
- 지속 메모리(SQLite + 벡터 검색), swarm 기반 병렬 에이전트 실행, 314개 MCP 도구, 30개 이상 플러그인 제공
- 소프트웨어 개발(코딩/리뷰/테스트) 워크플로에 최적화되어 있으며, KOSTAT의 영업/문서 업무 자동화와는 목적이 다르다

**왜 kostat-agent-plugin과 분리해서 검토하나:**
| 구분 | kostat-orchestrator (본 Plugin) | ruflo |
|------|-------------------------------|-------|
| 대상 업무 | PO/OOR/커미션/EOD 등 KOSTAT 고정 업무 | 범용 코딩 멀티에이전트 작업 |
| 실행 단위 | Skill(SKILL.md) + Python hooks | npm 패키지 + MCP 서버 + Rust 코어 |
| 설치 위치 | 이 저장소(GitHub) 자체 | 로컬 PC 프로젝트 폴더별 개별 설치 |
| 상태 저장 | `.ai-bridge/`, `task-status.json` | 자체 `agentdb.rvf` (벡터 DB) |

즉 ruflo는 **KOSTAT 업무에 직접 연결하지 말고**, 별도 실험/학습용 프로젝트 폴더에서 독립적으로 써보는 것을 권장한다.

## 2. 사전 준비

| 항목 | 요건 |
|------|------|
| Node.js | 20+ |
| npm | 9+ |
| Claude Code CLI | 로컬 PC에 설치되어 있어야 함 (`claude` 명령 사용) |

> `npx ruflo@latest doctor`가 Node/npm 버전, MCP 서버, 메모리 DB, API 키 상태를 자동 점검해준다.

---

## 3. 설치 및 초기화

로컬 PC(Windows PowerShell 또는 터미널)에서 KOSTAT 업무 폴더와 **별도의** 새 폴더를 만들어 진행한다.

```bash
mkdir ruflo-starter
cd ruflo-starter

# 대화형 초기화 wizard — 프로젝트에 .claude/, MCP 설정, hooks 생성
npx ruflo@latest init wizard

# 설치 상태 점검 (Node/npm 버전, MCP 서버, DB, API 키)
npx ruflo@latest doctor
```

`init wizard`는 대화형이므로 질문에 순서대로 답하면 된다(에이전트 종류, 메모리 백엔드 등 선택).

## 4. Claude Code와 MCP 연동

`ruflo-starter` 폴더 안에서 Claude Code를 실행하고, ruflo MCP 서버를 등록한다.

```bash
claude
claude mcp list                                   # 현재 등록된 MCP 서버 확인
claude mcp add ruflo -- npx -y ruflo@latest mcp start
claude mcp list                                   # ruflo가 추가됐는지 재확인
```

등록되면 Claude Code 세션에서 `mcp__ruflo__*` (또는 `mcp__claude-flow__*`) 네임스페이스의 도구를 바로 호출할 수 있다.

> **주의**: `claude mcp add`는 **해당 PC의 Claude Code 전역 설정**을 바꾼다. KOSTAT 업무용 Claude Code 세션과
> 같은 프로필을 쓴다면, ruflo MCP 서버가 항상 로드되어 도구 목록이 늘어난다는 점을 감안한다. 필요 없어지면
> `claude mcp remove ruflo`로 제거 가능.

## 5. Swarm 초기화 (hierarchical, 8-agent)

```bash
npx ruflo@latest swarm init \
  --topology hierarchical \
  --max-agents 8 \
  --strategy specialized
```

| 옵션 | 값 | 의미 |
|------|-----|------|
| `--topology` | `hierarchical` | 상위 Coordinator 1개가 하위 전문 에이전트들을 지휘하는 구조 (kostat-orchestrator의 Team 구조와 개념적으로 유사) |
| `--max-agents` | `8` | 동시에 존재 가능한 에이전트 수 상한 |
| `--strategy` | `specialized` | 에이전트를 역할별(코더/리뷰어/테스터 등)로 특화 배치 |

다른 옵션: `--topology mesh`(수평 협업), `--strategy balanced`(범용 배치) 등도 가능 — 실험 목적이면 `hierarchical + specialized`가 KOSTAT 팀 구조(Team A/B/C/D)와 비교하기 가장 직관적이다.

---

## 6. 상태 확인

```bash
npx ruflo@latest swarm status     # 현재 swarm 토폴로지 및 각 에이전트 실행 상태
npx ruflo@latest agent list       # 등록된 에이전트 목록 및 역할
```

## 7. 도입 여부 판단을 위한 옵션 정리

| 옵션 | 내용 | 장점 | 리스크 |
|------|------|------|--------|
| **A. 미도입 (현행 유지)** | kostat-orchestrator만 사용 | 안정적, 검증된 흐름 유지, 추가 학습 비용 없음 | 없음 |
| **B. 별도 실험 폴더에서만 사용** | `ruflo-starter`처럼 KOSTAT 업무와 분리된 폴더에서 개인 학습/실험용으로만 사용 | 신규 오케스트레이션 아이디어를 kostat-orchestrator 문서에 참고용으로 반영 가능 (이번 세션에서 이미 1건 반영: 의존성 그래프/지표 섹션) | 사내 업무 데이터와 무관해 리스크 낮음 |
| **C. KOSTAT-AGENT에 실제 연동** | ruflo MCP를 KOSTAT 업무 세션에 상시 등록 | 잠재적으로 병렬 처리/메모리 검색 강화 | PO/고객사 데이터가 외부 MCP 도구를 거칠 가능성, 검증되지 않은 서드파티 npm 패키지 의존성 증가, 유지보수 이중화 |

**권장**: 현재는 **옵션 B**(별도 폴더 실험)로 제한하고, 실제로 KOSTAT 업무에 도움이 되는 패턴이 확인되면 그때마다
kostat-orchestrator 등 기존 스킬 문서에 **개념만 이식**하는 방식(현재 접근)을 유지한다. 옵션 C는 고객사/PO 데이터가
외부 도구를 거치는 리스크가 있으므로, 도입 전 상사(김인섭 이사) 확인이 필요하다.
