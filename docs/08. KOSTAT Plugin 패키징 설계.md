## 2. Plugin 구현 방안

**.claude-plugin/plugin.json**
```json
{
  "name": "kostat-agent",
  "description": "KOSTAT 해외영업 자동화 — PO 업데이트, OOR 분석, 커미션 인보이스, EOD 회고",
  "version": "1.0.0",
  "author": {
    "name": "한준희",
    "email": ""
  },
  "homepage": "",
  "license": "UNLICENSED",
  "keywords": [
    "kostat",
    "semiconductor",
    "sales",
    "po-management"
  ]
}
```

### 2.2 Hook 설정 통합

Plugin의 `hooks/` 하위에 모든 Python 스크립트를 포함.  
설치 후 사용자가 `settings.json`에 hook 등록 필요 — 또는 Plugin 설치 시 자동 등록.

`hooks/hooks.json` (참조용 — Plugin이 자동 등록할 hook 설정):
```json
{
  "UserPromptSubmit": [
    "python {{PLUGIN_DIR}}/hooks/kostat-eod-detector.py"
  ],
  "PreToolUse": {
    "Write|Edit": [
      "python {{PLUGIN_DIR}}/hooks/kostat-gateguard.py",
      "python {{PLUGIN_DIR}}/hooks/kostat-autobackup.py"
    ]
  },
  "PostToolUse": {
    "Write|Edit": [
      "python {{PLUGIN_DIR}}/hooks/kostat-observe.py",
      "python {{PLUGIN_DIR}}/hooks/kostat-tracelogger.py"
    ]
  },
  "Stop": [
    "python {{PLUGIN_DIR}}/hooks/kostat-eod-stop.py"
  ]
}
```

**현재 Claude Code Plugin 시스템은 hook 자동 등록을 완벽히 지원하지 않을 수 있음.**  
→ 대안: `kostat-agent-setup` 스킬을 Plugin에 포함시켜, 사용자가 호출 시 settings.json에 hook 추가

## 3. 설치 방법 (설계)

### 방법 A: GitHub Marketplace (권장)

1. `kostat-agent-plugin`을 GitHub 리포지토리에 업로드
2. 아래 명령어로 설치:
   ```
   claude plugins install https://github.com/사용자/kostat-agent-plugin
   ```
3. 최초 실행 시 `kostat-agent-setup` 스킬이 자동 안내
4. 기술적 제약: 현재 Claude Code가 외부 리포지토리 Plugin 설치를 지원하는지 확인 필요

### 방법 B: 로컬 디렉토리 (확정)

```
git clone / 로컬에 복사
-> .claude/plugins/kostat-agent/ 에 직접 배치
-> settings.json에 "kostat-agent" Plugin 활성화:
    "enabledPlugins": {
      "kostat-agent@local": true
    }
```

### 방법 C: 마켓플레이스 등록 (장기)

- Claude Plugins 마켓플레이스에 등록
- 버전 관리, 업데이트 알림, 커뮤니티 기여 가능

## 5. 트레이드오프 분석

### 장점

| 항목 | 현재 (스킬 분산) | Plugin |
|------|-----------------|--------|
| 설치 | 수동 복사 2개 위치 | `plugins install` 한 번 |
| 버전 관리 | 없음 | package.json + Git tag |
| 이식성 | 낮음 (경로 의존) | 높음 (상대 경로) |
| 유지보수 | 파일 분산 추적 어려움 | 단일 디렉토리 |
| 공유 | 불가능 | GitHub / Marketplace |

### 단점 / 리스크

| 리스크 | 내용 | 대응 |
|--------|------|------|
| Hook 자동 등록 미지원 | Plugin이 settings.json hook을 자동 등록 못할 수 있음 | Setup 스킬에서 수동 등록 안내 |
| 경로 호환성 | 기존 스크립트가 절대 경로 하드코딩 | 상대 경로로 변경 필요 |
| Claude Code 업데이트 | Plugin 시스템 변경 시 호환성 깨질 수 있음 | 버전 고정, Release Note 추적 |
| 중복 관리 | Plugin + 기존 `.claude/skills/` 모두 남으면 충돌 | 마이그레이션 후 기존 스킬 삭제 |

## 7. 참고: Plugin SKILL.md 경로 변경

Plugin으로 전환 시 skill 파일 경로가 변경되므로,  
`settings.json`의 `enabledPlugins`에 Plugin 등록 후  
`.claude/skills/`의 기존 KOSTAT 스킬들을 제거해야 중복 등록을 방지합니다.

```
변경 전: .claude/skills/kostat-po-update/SKILL.md
변경 후: .claude/plugins/kostat-agent/skills/kostat-po-update/SKILL.md
```

Claude Code는 `skills/` 디렉토리와 `enabledPlugins` 모두에서 skill을 발견하면 중복 등록하므로,  
Plugin 활성화 후 기존 `.claude/skills/kostat-*` 디렉토리를 삭제해야 합니다.

## 8. v2.0 업데이트 — 단일 플러그인 → 5개 플러그인 분할

> **상태**: 🟢 구현 완료
> **계기**: [요즘IT — 폴더 단위로 설정 쪼개기](https://yozm.wishket.com/magazine/detail/3931/)에서 소개된
> "폴더마다 필요한 것만 로드한다" 원칙을 이 저장소에 적용

### 8.1 문제
v1.x는 스킬 11개 + hook 9개가 모두 하나의 플러그인에 묶여 있어, PO 작업만 하는 폴더에서도
EOD 회고 hook·모닝 브리핑 스킬 등 관련 없는 자동화가 항상 함께 로드되었습니다.

### 8.2 제약 확인
Claude Code plugin 시스템은 다음 두 가지를 지원하지 않습니다 (공식 문서 확인):
- `skills/`를 한 단계 더 중첩하는 것 (`skills/<name>/SKILL.md` 고정 depth-1 스캔만 지원)
- hook을 특정 스킬에만 스코핑하는 것 (이벤트 타입 + 도구 매처 정규식이 전부)

따라서 "필요한 것만 로드"를 실현하는 유일한 방법은 **플러그인 자체를 업무 단위로 쪼개는 것**이었습니다.

### 8.3 결과 구조
```
plugins/
├── kostat-core/         ← 필수. orchestrator·memory-loader·memory-ticket·skill-check·tal
│                           + gateguard·autobackup·observe·tracelogger·handoff-writer·
│                             ai-bridge·workspace-router·compact (hook 8개)
├── kostat-po/           ← po-update, hk-po-update
├── kostat-oor/          ← oor-weekly
├── kostat-commission/   ← commission-invoice
└── kostat-eod/          ← eod-retrospective, morning-briefing
                            + eod-detector·eod-sessionstart·eod-stop (hook 3개)
```
`.claude-plugin/marketplace.json`이 5개 플러그인을 각각 `source: "./plugins/kostat-*"`로 등록합니다.
`references/` 아래 있던 매핑 문서(column-map, field-mapping, rate-tables, xview-mapping)는
그 문서를 참조하는 스킬 폴더 안(`skills/<skill>/references/`)으로 이동해, SKILL.md의 기존 상대경로 링크와도 맞췄습니다.

### 8.4 트레이드오프
| 항목 | v1.x (단일 플러그인) | v2.0 (5개 분할) |
|------|----------------------|------------------|
| 불필요한 로드 | 항상 11개 스킬 + 9개 hook 전부 | 폴더별로 필요한 플러그인만 |
| 설치 | 1회 install | kostat-core + 필요한 도메인 플러그인, 여러 번 install |
| 유지보수 | 파일 하나만 보면 됨 | 도메인 경계를 넘는 변경 시 여러 plugin.json 확인 필요 |
| 신규 스킬 추가 | skills/에 폴더만 추가 | 어느 플러그인 소속인지 먼저 결정해야 함 |

단일 저장소·단일 marketplace.json 안에서 여러 plugin을 등록하는 구조이므로, 커밋 이력과 배포는 여전히 한곳에서 관리됩니다.
